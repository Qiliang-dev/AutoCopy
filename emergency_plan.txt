【快速诊断清单】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

在日志最后查找这些关键词：

□ "Windows fatal exception: code 0x80010001"
  → COM冲突，schedule_cell_check可能还在访问Excel
  
□ "Windows fatal exception: code 0xc0000374"
  → 堆损坏，pyperclip可能有并发访问
  
□ "Windows fatal exception: code 0xc0000005"
  → 访问违规，可能是新问题
  
□ 没有错误信息，日志突然停止
  → 系统级崩溃或Excel进程问题


【错误代码速查表】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

0x80010001 - COM服务器忙或已死亡
  原因：Excel COM对象被多个地方同时访问
  修复：禁用schedule_cell_check

0xc0000374 - 堆损坏
  原因：pyperclip被多个线程同时访问
  修复：确保所有pyperclip调用都有锁

0x800401f0 - COM对象不可用
  原因：Excel COM对象未正确初始化
  修复：添加COM初始化检查

0xc0000005 - 访问违规
  原因：访问了无效内存地址
  修复：需要具体分析

如果程序频繁崩溃，可以尝试：

方法1：降低使用频率
  - 不要快速连续复制
  - 每次复制后等待2-3秒
  - 让Excel有时间处理

方法2：重启Excel
  - 定期关闭并重新打开Excel
  - 清除Excel进程缓存
  - 重新连接AutoCopy

方法3：使用旧版本
  - 回退到V1.88
  - 虽然也会崩溃，但可能更可预测
  - dist\Autocopy_V1.88.exe

方法4：手动模式
  - 不使用"Start Monitoring"
  - 只使用"Paste Now"按钮
  - 手动控制粘贴时机

如果AutoCopy完全不可用：

选项A：使用Excel的录制宏功能
  1. Excel菜单 → 开发工具 → 录制宏
  2. 手动复制粘贴一次
  3. 停止录制
  4. 之后可以快捷键运行宏

选项B：使用AutoHotkey脚本
  (需要安装AutoHotkey)
  简单的复制粘贴自动化

选项C：纯手动
  Ctrl+C, 点击Excel, Ctrl+V
  虽然慢但绝对稳定
